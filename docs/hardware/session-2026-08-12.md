## Trans temp (OBD-15 residuals)
- `ATSH7E1` + `22 05 43` → **`7F 22 11` serviceNotSupported — hypothesis FALSIFIED**
  (no UDS 22 in default session; we do not change sessions — read-only charter)
- `ATSH7E1` + `21 30` → **positive `61 30`, 26-byte record — hypothesis CONFIRMED**
- Record (24 data bytes): `00 13 00 00 | 00 00 00 08 04 00 DD | 8E FF F3 FF F3 00 00 |
  86 18 00 08 00 00`
- Byte 11 (`8E→8D→93`, i.e. 92→91→97°C via raw−50) tracks engine coolant — TCU-side
  coolant, moved +6°C during the drive ✓
- **Byte 18 (`86` = 84°C via raw−50) = trans-temp CANDIDATE** — value plausible, sat
  rock-steady through idle, a 90s converter stall, AND a 15-min drive. Consistent with
  722.9 thermostatic cooler regulation (~85°C setpoint) on an already-warm trans, but
  movement-based proof was NOT obtained.
- 🖐 **REMAINING PROOF: cold-start capture.** One `2130` poll on a cold morning before
  driving: byte 18 ≈ ambient+50 then climbs toward 0x86 → PROVEN temp + offset + −50
  encoding. Byte 18 = 0x86 cold → it's a setpoint constant, search continues.
- Byte pairs 13/15 (`FFF3→FFF6→FFFF` signed 16-bit) move with converter load — slip/torque
  related, uncatalogued. data[1] `13→12`, byte 19 `18→10→00` — state fields, uncatalogued.
- Encoding note: raw−50 (MTH algebraic derivation) makes BOTH temps coherent
  simultaneously; −40 leaves no self-consistent assignment. Independent field support
  for the Sprint-2a decode.

## Session lessons (process)
- Console UI screen-scraping is the wrong capture tool for drives: phone locked mid-drive,
  15 poll cycles tapped a dark screen, zero data. → OBD-48: headless TX/RX traffic logging
  (debug builds, logcat tag) so capture sessions run screen-off. Prereq for OBD-41 logger.
- `svc power stayon` does not WAKE a sleeping screen; set screen_off_timeout + verify the
  first cycle's capture before declaring a logger live.
